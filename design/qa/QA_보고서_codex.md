## 2. 환경과 방법

- Windows, Node v24.15.0, Playwright 1.63.0, 설치된 Chrome 154.0.8037.57, `channel: 'chrome', headless: true`.
- 휴대폰 본 플레이는 `isMobile: true`, `hasTouch: true`, DPR 3, 390×844. PC는 DPR 1, 1366×800. 보충 검사에서 844×390 가로 휴대폰, 768×1024 태블릿 및 실행 중 크기 변경도 확인했다.
- `tests/serve.mjs`의 `base()`로 로컬 정적 서버를 실행했다. 외부 요청은 브라우저 라우팅에서 차단했다. 인터넷·git 명령을 사용하지 않았다.
- 새 브라우저 컨텍스트에서 `localStorage.clear()` 후 이야기 시작·학습 방식 선택. 네 본 플레이에는 장 바로가기, 선생님 모드, 강제 승리, 상태 변경용 테스트 함수를 사용하지 않았다.
- 이동은 발 충돌 상자 `(x-6,y-5)~(x+6,y)`와 `blocked()`를 이용한 8px BFS로 길을 계산하고 방향키 또는 실제 터치 끌기로 수행했다. 이동 입력은 최대 440ms 단위로 나누고 현재 위치·대상을 다시 읽었다. 목표 NPC 근처에서 `near()`를 확인한 후 E/말 걸기 단추를 눌렀다. 출구에는 걸어 들어갔다.
- m·fb는 CDP `Input.dispatchTouchEvent`의 touchStart→touchMove→touchEnd로 왼쪽 조이스틱을 끌었고 단추는 Playwright `tap()`으로 눌렀다. fa·fc는 방향키/E/Space/Q와 선택 단추의 Enter를 사용했다. 단추 포커스 지정과 텍스트 입력에는 Playwright 기능을 사용했으므로, 처음부터 끝까지 Tab만으로 탐색하는 접근성 검사는 아니다.
- 맵 전투는 적에게 접근해 베기·사용 가능한 도술을 입력했다. 화면의 붉은 픽셀을 읽어 공격 예고가 감지되면 후퇴했다. fa/fb/fc 본 플레이 후퇴 이벤트는 각각 8/2/19회다. m 본 플레이에서는 이 감지가 발동하지 않아, 별도의 휴대폰 보충 전투에서 공격을 기다렸다가 조이스틱으로 후퇴하는 검사를 추가했다. 픽셀 판별은 시각 신호의 근사치이며 모든 후퇴가 무피해 회피였다는 뜻은 아니다.
- 카드 전투는 표시된 `.intent`와 손패를 읽고 공격·계책·진법·둔갑술·회복·신물 중 실제 카드를 눌렀다. 각 경로의 모든 전투를 진행했다.
- DOM 변경 시 화면 본문을 수집했고, 읽기 전용 상태를 약 100ms 간격으로 기록했다. 전투 중에는 requestAnimationFrame 간격을 수집했다. 게임 상태 대신 QA 기록 배열만 페이지에 추가했다.
- 본 플레이 스크립트에는 전체 55분 제한, 진행 변화 없음 90초 감지, 이동 중 5초 제자리 감지와 스크린샷·우회가 있다. 보충 브라우저 스크립트에도 시간 제한과 유한 반복을 두었다. 본 플레이의 `stuck5` 발생은 네 경로 모두 0회였다.
- 기존 파일 330개의 SHA-256 기준값과 검사 후 값을 비교했다. 변경 0개. 새 파일은 허용된 세 디렉터리 안에만 만들었다.

**보충 검사와 한계:** `probe.mjs`는 `file://` 새 게임 및 `?ch=ch1`, `?ch=ch7`을, `terrain.mjs`는 `?ch=ch5`를 사용했다. `--card-probe`는 `?path=f&ch=ch5`, `--dodge-probe`는 `?path=m&ch=ch7`에서 특정 현상을 재검사했다. 이 결과를 네 경로의 완주 시간·능력치·승패에 합산하지 않았다. `--lesson-probe`는 바로가기 없이 새 m 게임부터 4장까지 다시 걸었다.

실물 휴대폰의 발열·배터리·손가락 가림·한 손 조작감, Safari/Firefox, 실제 소리 청취는 검사하지 못했다. 헤드리스 Chrome의 터치 에뮬레이션 결과다. 네 본 플레이의 천우신조는 모두 0회였고, 추가 휴대폰 전투 검사에서 기력이 고갈되어 천우신조 안내·회복·전투 재개를 확인했다. 카드 전투에서의 천우신조는 미검증이다. 외부 문헌을 열지 않았으므로 문학 사실의 독립적인 원전 대조도 미검증이다. 캔버스의 이름표·공격 숫자는 스크린샷과 읽기 전용 대상 정보로 확인했으며 모든 프레임을 OCR로 전사한 것은 아니다.

첫 m 자동화 시도 두 번은 설정 창 닫기 선택자 오류와 탭 대기 시간 초과로 중단됐다. 게임 결함으로 집계하지 않았고 `m_attempt1/`, `m_attempt2/`에 보존했다. 표의 m은 이후 완주한 실행이다. 본 m 실행은 수련 중 재개를 검사했다. 차시 종료 감지 문자열이 실제 오탈자와 달라 그 시점의 재개 검사를 놓친 것을 발견한 뒤, 별도 새 게임으로 차시 재개를 다시 확인했다.

### 이어 하기·결과 화면

- **4장 끝 → 새로고침 → 타이틀 이어 하기 → 5장: 정상.** 바로가기 없는 `lesson_probe/run_m.json`의 `lessonValidated: true`, `lesson_probe/m_025_lesson_end_before.png`, `m_026_lesson_end_after.png`, `m_027_lesson_validated.png`가 증거다. 안내 문구에는 QA-005가 있다.
- **5장 수련 중 → 새로고침 → 이어 하기: 진행은 가능하지만 라운드와 보상 저장이 불일치.** QA-001 참조.
- 네 경로 모두 목차 엮기, 낯선 대목, 표지·목차, 편람 열람, 디브리핑 입력, 이미지로 저장을 진행했다. 깊이 읽기는 진행 중 대목 문제를 포함하여 최종 10/10이다. 디브리핑에는 같은 문장을 입력했으므로 학습 답변의 질을 검증한 것은 아니다.

### 연타·일시정지·화면 크기

- 대화 중 E 20회 연타로 대화가 임의 진행되거나 겹쳐 열리지 않았다. 닫은 직후 E는 재개방하지 않았고, 잠시 기다린 뒤 E는 정상적으로 다시 열었다. 다음 단추 빠른 8회 클릭 검사에서도 진행 정지나 예외가 없었다. `probe.json`, `probe_mobile.json`의 연타 이벤트 참조.
- 적이 살아 있는 맵 전투 중 목차·편람·설정을 각각 열고 약 1.1~1.2초 비교했다. 적 좌표·주인공 좌표·기력이 동일했다. 닫으면 전투가 이어졌다. 본 m 및 보충 전투에서 확인했다.
- 390×844, 844×390, 768×1024, 1366×800으로 세계·대화 화면을 바꿨고, 카드 보충 검사에서는 전투 화면도 바꿨다. 확인한 화면에서 진행 단추가 닿지 않는 곳으로 사라지거나 가로로 잘려 진행을 막는 현상은 없었다.
- 가로 휴대폰 카드 전투는 손패와 적 의도는 보이지만, 주인공 기력·튜토리얼까지 한 번에 보기 어렵고 본문 스크롤이 필요했다. 진행은 가능하므로 결함 건수 대신 가로 배치 개선 의견으로 남긴다.
- `file://`로 새 게임을 시작해 전기수 대화·성별 선택까지 진행하고, 새로고침 후 이어 하기로 저장을 유지하는 것을 PC/터치 컨텍스트에서 확인했다. **file://로 네 경로 전체를 다시 완주한 검사는 아니다.**

### 교육 내용

1장 고귀한 혈통, 2장 기이한 출생, 3장 비범한 능력, 4장 어린 시절의 위기, 5장 구출·양육·수련, 6장 성장 뒤 위기, 7장 극복·성취로 물음과 사건이 연결됐다. fc는 남장·출전을 생략하고 집 안의 도술·방어로 위기를 해결하며 분기 차이가 결말·표지에 반영됐다.

붉은 낙관의 실제 작품 설명과 청록색 게임 설정 표시를 확인했다. 특히 서로 다른 작품의 요소를 게임에 섞었다는 설명, 『박씨전』이 7단계에 정확히 맞지 않는다는 편람, 여성 영웅의 결말 차이를 비교하는 디브리핑은 학습에 유용하다. 『이학사전』의 자발적 정체 공개와 게임 속 의원의 정체 발견 차이도 작품 설명에서 구분한다. 이 단서들이 서장의 “누구나”와 충돌하는 QA-004는 수정하는 편이 좋다.

독립적인 문학 사실 오류를 확정하지는 않았다. 로컬 자료와 게임 내 설명의 일관성을 검토한 결과이며, 출전·인용의 정확성이나 작품별 이본 차이까지 외부 원전으로 검증한 결과는 아니다. 단계가 약한 작품도 같은 일대기 틀에 놓았을 때 생기는 차이를 교사가 짚어 주면 기계적인 단계 암기를 줄일 수 있다.

### 길 찾기·난이도·수업 시간

목표 문장, 노란 느낌표와 화면 밖 화살표 덕분에 다음 행동은 대체로 명확했다. 관측한 한 번의 목표 접근 중 긴 구간은 m 활터 15.45초, fa 서당 12.29초, fb 도사 15.22초, fc 활터 8.96초였다. 상시 NPC 접근까지 포함한 최장은 m 종 18.54초였다. 이 값은 `navigate`→`arrived` 간격으로 캡처와 입력 대기도 포함하며, 공간 좌표를 아는 봇의 이동 시간이다. 사람이 목표를 알아차리는 데 걸린 시간이나 모든 출구의 시간을 뜻하지 않는다. 읽기 전용 대상 좌표를 사용했기 때문에 “학생도 헤매지 않는다”는 결론은 낼 수 없다.

선택한 장소가 실제 이동으로 이어지고, 수련·전투·이야기 전개가 번갈아 나오는 점은 참여감을 준다. 반면 매 장 마을 상시 인물에게 말을 걸면 같은 말이 반복되며, QA-002가 반복 탐색의 보상까지 해친다. 상시 대사를 현재 사건에 맞춰 갱신하거나 새 대사를 표시하는 방식이 도움이 된다.

이번 봇은 맵 전투를 6.7~26.0초 안에 해결했다. 카드전은 1~7턴이었다. m의 허깨비 장수는 한 턴에 끝나 첫 전투에서 의도·방어를 익힐 기회가 적었으나, m에는 재개 중복 보상도 있었으므로 정상 성장 전체의 균형 문제로 확정하지 않았다. fa/fb 후반은 더 여러 턴을 요구했다. 네 경로 모두 천우신조 0회라는 사실만으로 초보 학생에게 쉽다고 단정할 수 없다. 조이스틱과 공격 단추가 좌우로 나뉜 배치는 한 손일 때 손가락을 옮겨야 하므로 실제 기기에서의 관찰이 추가로 필요하다. 좌우 배치 선택이나 한 손 보조 조작을 검토할 수 있다.

**서장~4장을 45분 수업 안에 마치는 것은 가능성이 있으나 여유가 크다고 보기는 어렵다.** 네 실행에서 해당 구간의 중복 제거 화면 글은 약 7,100~7,300자였다. 읽기·낱말 확인을 분당 400~600자로 가정하면 약 12~18분, 초보 이동·조작 적응 8~12분, 선택·단계 물음·짧은 토의 8~12분, 시작 안내 3~5분으로 **약 31~47분**이다. 이는 학생 실측이 아닌 명시적 가정의 추정이다. 모든 상시 NPC를 읽지 않으면 짧아지고, 깊이 읽기·기기 문제·토의가 길어지면 늘어난다. 첫 시간은 조작 시범을 짧게 하고 4장 끝 저장 안내를 분명히 보게 하는 운영이 적절하다. 봇의 약 5~7분 구간 시간을 학생 소요 시간으로 환산하지 않았다.

## 7. 다시 돌리는 법과 증거

프로젝트 루트 `E:\github\영웅소설`의 PowerShell에서 실행한다. 기존 `tests/node_modules`를 사용하며 별도 설치나 빌드가 없다. 아래는 순서대로 실행하는 명령이다. 재실행하면 같은 QA 파일명이 덮어써질 수 있으므로 현재 증거를 보존하려면 먼저 별도 허용 디렉터리에 복사한다.

```powershell
node tests/codex-qa/play.mjs m
node tests/codex-qa/play.mjs fa
node tests/codex-qa/play.mjs fb
node tests/codex-qa/play.mjs fc
node tests/codex-qa/play.mjs m --lesson-probe
node tests/codex-qa/play.mjs fc --card-probe
node tests/codex-qa/play.mjs m --dodge-probe
node tests/codex-qa/probe.mjs
node tests/codex-qa/probe.mjs --mobile
node tests/codex-qa/terrain.mjs
node tests/codex-qa/book-evidence.mjs
node tests/codex-qa/analyze.mjs
node tests/codex-qa/coverage.mjs
node tests/codex-qa/gallery.mjs
node tests/codex-qa/final-metrics.mjs
node tests/codex-qa/audit-report.mjs
node tests/codex-qa/integrity.mjs --check
```

카드 손패와 NPC 이동은 달라질 수 있어 시간·피해·파일 일련번호가 그대로 재현되지는 않는다. 현재 보존된 실행의 숫자를 본 보고서에 사용했다. `integrity.mjs`를 인수 없이 실행하면 기준값을 새로 만들므로 기존 파일 불변 확인에는 반드시 `--check`를 사용한다.

| 자료 | 용도 |
|---|---|
| `run_m.json`, `run_fa.json`, `run_fb.json`, `run_fc.json` | 시각, 선택, 이동, 대화, 전투, 저장 상태, 오류, 표본·스크린샷 목록 |
| `texts_<경로>.json`, `review_<경로>.txt` | 실제 화면 글 원문 및 중복 제거 검토본 |
| `summary.json`, `coverage.json` | 장·전투 통계, 전체 상시 대상·대사 변형의 방문 증거 |
| `result_m.png`, `result_fa.png`, `result_fb.png`, `result_fc.png` | 다운로드한 표지·목차 결과 |
| `probe.json`, `probe_mobile.json`, `terrain.json` | 파일 실행·연타·크기 변경·일시정지·지형 보충 검사 |
| `lesson_probe/`, `card_probe/`, `dodge_probe/` | 차시 재개, 방어 안내, 휴대폰 후퇴의 독립 재현 |
| `gallery.html`, `gallery.png` | 10개 맵 시각 검토용 모음 |
| `integrity.json` | 검사 시작 당시 기존 파일 해시 기준값 |

재현하지 않은 코드 의심을 확인된 버그로 올리지 않았다. 본 보고서의 원인 추정은 수정 제안이며, 게임 코드에 반영한 변경은 없다.
